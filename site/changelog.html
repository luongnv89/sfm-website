Changelog

Product/Service: sfm (SSH Fleet Monitor)

sfm has no public release yet. Each release will be listed here, newest first, with what is new, improved and fixed.

Unreleased: the current development build

New

  • See every host's health, risk, CPU, memory and disk on one overview, as cards or as a sortable table.
  • Get update and CVE findings for macOS, Debian, Ubuntu and Arch hosts, with known-exploited issues ranked first.
  • Open any finding for numbered fix steps to copy, with a verify step and a rollback note.
  • Run a Lynis audit on a macOS or Debian host after you grant consent for it.
  • Ask an AI agent about your fleet through six read-only MCP tools, or call the same tools from the command line as JSON.
  • Follow trends over time, put the fleet on a wall screen and see it as a network topology.
  • Export the fleet report as ECS NDJSON for Wazuh or as Prometheus text for Grafana.
  • Add the machine sfm runs on, with no SSH server and no key. Its public IP stays up to date: after each of its status scans, sfm asks ipify for it, unless sfm runs with --offline.
  • Monitor hosts on a private network through another machine that runs sfm (relay mode), in chains up to 8 relays deep.
  • Set how often each host gets a status scan, from every minute to once a day, or turn it off.
  • Disable monitoring of a host and keep its data, or remove the host and everything sfm stored about it.
  • See when the CVE data was last updated, and refresh CVE statuses without a new scan.
