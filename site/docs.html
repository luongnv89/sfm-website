Requirements

  • To run sfm: a Mac (Apple Silicon or Intel) or a Linux machine (x64 or arm64). There is no Windows build.
  • Hosts to watch: reachable over SSH with public-key sign-in, running macOS, Debian, Ubuntu or a derivative, or Arch Linux or a derivative.
  • Known host keys: each host's key in your ~/.ssh/known_hosts. sfm never trusts a key on first use: connect once with ssh and accept the fingerprint yourself.
  • Only for pasted or generated keys: the OS keychain. On Linux that means secret-tool (the libsecret-tools package) and an unlocked keyring in a desktop session.

Install

sfm is a single binary, and nothing is installed on your hosts. Builds are not public yet: request early access to be told when one is available.

First run

sfm hosts import
sfm hosts test --all
sfm web

sfm hosts import reads your ~/.ssh/config. sfm hosts test --all signs in to each host and explains any failure. sfm web then prints:

sfm web: listening on http://127.0.0.1:PORT/ (Ctrl-C to stop)
Open http://127.0.0.1:PORT/#token=TOKEN

Open the link. The token is new on every start, and the dashboard shows your hosts once their first status scan has run.

Two other ways to add a host:

sfm hosts add admin@server.example.com
sfm hosts add --local

--local adds the machine sfm runs on. It needs no SSH server and no key.

AI agents

sfm mcp lets Claude Code, Codex or any other stdio MCP client answer questions about your fleet from stored scan data, with no shell. For Claude Code, put this in a project's .mcp.json:

{
  "mcpServers": {
    "sfm": {
      "command": "sfm",
      "args": ["mcp"],
      "env": {
        "SFM_DATA_DIR": "/home/you/.local/share/sfm",
        "SSH_AUTH_SOCK": "/run/user/1000/ssh-agent.socket"
      }
    }
  }
}

For Codex, in ~/.codex/config.toml:

[mcp_servers.sfm]
command = "sfm"
args = ["mcp"]
env = { SFM_DATA_DIR = "/home/you/.local/share/sfm", SSH_AUTH_SOCK = "/run/user/1000/ssh-agent.socket" }

Use the full path to the binary if sfm is not on the client's PATH, and your own agent socket (echo $SSH_AUTH_SOCK).

Troubleshooting

SymptomFix
sfm mcp exits with status 1 and names a pathThere is no database at that path, and sfm mcp never creates one. Add hosts and run sfm web first, and set SFM_DATA_DIR in the MCP client's env block: clients often start servers with a reduced environment.
A connection test stops at a new or changed host keysfm reads known_hosts and never writes it. Check the fingerprint and accept the key with ssh, as sfm hosts test explains.
--paste and --generate are disabled on a headless Linux serverThey need the Secret Service through secret-tool and an unlocked keyring. Use ssh-agent or a key path instead.
refresh_host_status cannot sign in from an MCP clientIt needs SSH_AUTH_SOCK in the client's env block for ssh-agent keys, and it never asks for a passphrase.
macOS shows privacy prompts for your terminal while this machine is scannedExpected when sfm is started from a GUI terminal: the scan's commands run as that terminal's child processes.
The Lynis audit will not run on this machineIt refuses to run as root. Run sfm as a normal user to audit the machine it runs on.
