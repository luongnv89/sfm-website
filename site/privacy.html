Privacy Policy

Product/Service: sfm (SSH Fleet Monitor) and this website, sfm.luongnv.com
Effective date: 23 November 2026

Summary: This website sets no cookies and runs no analytics, and the sfm application has no telemetry. If you email sfm@luongnv.com, the author receives your address and your message and uses them to answer you.

1. Information we collect

  • This website. The site is static pages with no forms, no accounts, no cookies and no scripts. It is hosted on GitHub Pages, and GitHub, as the host, logs the IP address of each visitor for security purposes (see GitHub's note on Pages data collection). The author does not receive these logs.
  • Email you send. When you write to sfm@luongnv.com, the author receives your email address, the name your mail client sends and whatever you write.
  • The sfm application. sfm runs on your own machine. Its host inventory, scan results, findings and audit log stay in a local database in sfm's data directory on that machine. sfm has no telemetry and no hosted service, so none of it reaches the author.

2. How we use it

  • Email: to answer you and, if you asked for early access, to tell you when a build is available.
  • Nothing else is collected, so nothing else is used.

3. Cookies and analytics

None. Each page loads only its own files from sfm.luongnv.com: no analytics, no tracking pixels, and no fonts or scripts from another site.

4. Sharing and processors

  • GitHub hosts this website on GitHub Pages.
  • Cloudflare serves the DNS records of luongnv.com and routes mail sent to sfm@luongnv.com to the author's mailbox (Cloudflare Email Routing). Web traffic to this site does not pass through Cloudflare's proxy.
  • The sfm application. Besides the SSH connections to your own hosts, its only network traffic is downloading vulnerability data from seven allowlisted HTTPS sources: the Debian Security Tracker, Canonical's Ubuntu OVAL files, the Arch Security Tracker, the CISA Known Exploited Vulnerabilities catalog, the SOFA macOS and Safari feeds, and OSV.dev. OSV.dev receives CVE IDs only, never a package, version or hostname; those IDs are the fix-available CVEs found on your Debian hosts.
  • AI clients. If you connect an AI client to sfm mcp, that client may send sfm's answers to its model provider. The same goes for a report you export with sfm report: once data leaves sfm, sfm no longer protects it.

5. Retention

  • Email: no retention period is set. Messages stay in the author's mailbox until they are deleted.
  • sfm's local data stays on your machine until you delete it. sfm hosts remove ALIAS --yes deletes everything sfm stored about one host.

6. Your choices

  • To ask what the author holds about you, or to ask for your emails to be deleted, write to sfm@luongnv.com.
  • To run sfm with no outbound request for vulnerability data, start it with sfm web --offline or set SFM_OFFLINE=1.

7. Changes to this policy

Changes are published on this page with a new effective date. The page's history is public in the website's repository.
